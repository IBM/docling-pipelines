== Vector Storage and Retrieval

`VectorDBOperator` indexes document embeddings into a vector database for similarity
search, semantic retrieval, and RAG. It supports OpenSearch and Milvus through a
ports-and-adapters design — switching providers requires only a configuration change.

=== VectorDBOperator Overview

* **Short name:** `vectordb`
* **Category:** VectorDB

The operator sits at the end of the standard RAG pipeline:

----
Ingest → Extract → [Quality] → Chunk → Embed → VectorDBOperator
----

It does not add or remove columns — the input table is returned unchanged to allow
chaining with downstream operators such as `document_set`.

==== Core Parameters

[cols="2,1,3",options="header"]
|===
|Parameter |Default |Description

|`provider`
|Required
|Vector DB provider: `opensearch` or `milvus`.

|`create_index`
|`true`
|Create the index/collection if it does not exist. Safe to set `true` on re-runs.

|`vector_dimension`
|auto
|Embedding dimension. Auto-detected from data if omitted (recommended).

|`doc_id_column`
|`"doc_id_hash"`
|Column used as the primary key.

|`embeddings_column`
|`"embeddings"`
|Column containing dense embeddings.

|`sparse_embeddings_column`
|—
|Column containing sparse embeddings for hybrid search.

|`provider_config`
|Required
|Provider-specific settings (see sections below).
|===

=== OpenSearch

==== Quick-Start Example

[source,json]
----
{
  "type": "vectordb",
  "name": "index_documents",
  "depends_on": ["embed"],
  "config": {
    "provider": "opensearch",
    "vector_dimension": 768,
    "provider_config": {
      "index_name": "my_documents",
      "host": "localhost",
      "port": 9200,
      "use_ssl": false,
      "verify_certs": false
    }
  }
}
----

==== Engine Selection Guide

[cols="1,3",options="header"]
|===
|Engine |Best for

|`nmslib`

=== Milvus

==== Auth Types

[cols="1,3",options="header"]
|===
|`auth_type` |Description

|`lite`
|Milvus Lite — embedded, container-free local mode. Uses a `.db` file. Only `FLAT` index type supported.

|`standalone`
|Standard Milvus server. Connect by host/port.

|`grpc`
|gRPC connection.

|`uri`
|Pre-constructed URI string.

|`token`
|Token-based authentication (Zilliz Cloud).
|===

==== Milvus Lite (Container-Free)

[source,json]
----
{
  "type": "vectordb",
  "name": "index_documents",
  "depends_on": ["embed"],
  "config": {
    "provider": "milvus",
    "create_index": true,
    "provider_config": {
      "collection_name": "local_docs",
      "auth_type": "lite",
      "uri": "./data/milvus/local_docs.db",
      "index_type": "FLAT",
      "metric_type": "COSINE",
      "batch_size": 100
    }
  }
}
----

IMPORTANT: Set `enable_micro_batching: false` in `global_config` when using Milvus Lite
because it holds a single-process file lock that is incompatible with concurrent batches.

=== DocumentSetOperator — Persistent Storage

* **Short name:** `document_set`
* **Category:** Storage

`DocumentSetOperator` stores pipeline data at rest in DuckDB using an upsert-based
get-or-create pattern. It is pass-through — the input table is returned unchanged.

Use it to checkpoint processed documents at any pipeline stage before or after indexing.

[source,json]
----
{
  "type": "document_set",
  "name": "store_documents",
  "depends_on": ["extract"],
  "config": {
    "document_set_name": "research_papers",
    "description": "Processed research papers",
    "metadata": {
      "department": "research",
      "year": 2024
    }
  }
}
----

[cols="2,1,3",options="header"]
|===
|Parameter |Default |Description

|`document_set_name`
|Required
|Name of the document set to create or update.

|`description`
|`""`
|Human-readable description.

|`metadata`
|`{}`
|Arbitrary JSON stored as document set metadata.

|`document_set_id`
|—
|UUID of an existing document set to update.

|`database_path`
|`data/duckdb/document_sets.duckdb`
|File path for the DuckDB database.
|===

Common placements:

[source]
----
Ingest → Extract → [DocumentSetOperator] → Quality → [DocumentSetOperator] → Chunk → Embed → VectorDB
----

=== ACL-Based Retrieval

When documents are indexed with an `allowed_users` column (produced by `ACLOperator`),
the REST API enforces row-level access control at query time.

==== Architecture

[source]
----
Client → POST /api/v1/documents/search
          └── ACLQueryBuilder
                └── OpenSearch query with "term" filter on allowed_users
                        └── Returns only documents where current_user ∈ allowed_users
----

Key security properties:

* Documents without an `allowed_users` field are **not accessible** (fail-closed).
* Documents with an empty `allowed_users` array are **not accessible**.
* The API returns `404 Not Found` for both non-existent and unauthorised documents
  (security by obscurity — prevents document ID enumeration).
* ACL filtering is applied at the OpenSearch query level, not in application code.

==== Index Mapping (Required for ACL)

The `allowed_users` field must be a `keyword` type in the OpenSearch mapping to support
exact-match filtering:

[source,json]
----
{
  "mappings": {
    "properties": {
      "content":       { "type": "text" },
      "allowed_users": { "type": "keyword" },
      "embeddings":    { "type": "knn_vector", "dimension": 768 }
    }
  }
}
----

==== End-to-End ACL Pipeline

[source,json]
----
{
  "flow_name": "acl-rag-pipeline",
  "flow": [
    {
      "type": "ingest_source",  "name": "ingest",

=== OpenSearch Setup Reference

For local development, start OpenSearch with Docker or Podman:

[source,bash]
----
docker run -d --name opensearch \
  -p 9200:9200 -p 9600:9600 \
  -e "discovery.type=single-node" \
  -e "OPENSEARCH_INITIAL_ADMIN_PASSWORD=Admin@12345" \
  opensearchproject/opensearch:2.13.0
----

Check cluster health:

[source,bash]
----
curl -k -u admin:Admin@12345 https://localhost:9200/_cluster/health
----

For additional configuration options, schema templates, and environment setup scripts, see
`docs/integrations/opensearch/` in the repository.

=== Milvus Setup Reference

For local development, start Milvus with Docker Compose:

[source,bash]
----
curl -sfL https://raw.githubusercontent.com/milvus-io/milvus/master/scripts/standalone_embed.sh -o standalone_embed.sh
bash standalone_embed.sh start
----

Or use Milvus Lite (no Docker required) — set `auth_type: "lite"` and point `uri` to a
local `.db` file as shown in the Milvus Lite example above.

For full Milvus configuration options, see `docs/integrations/milvus/README.md`.

=== Troubleshooting

[cols="2,3",options="header"]
|===
|Symptom |Fix

|`DocpipeException: index_name is required`
|Add `"index_name"` inside `provider_config` for OpenSearch.

|`DocpipeException: collection_name is required`
|Add `"collection_name"` inside `provider_config` for Milvus.

|`ConnectionError` to OpenSearch
|Verify `host` and `port`; ensure OpenSearch is running.

|`Index already exists` on re-run
|Safe — the operator skips creation if the index exists. `create_index: true` is idempotent.

|`KeyError: doc_id_hash`
|Ensure `DocIdHashOperator` or `ExtractOperator` runs before `VectorDBOperator`.

|`KeyError: embeddings`
|Ensure `EmbeddingsOperator` runs before `VectorDBOperator`.

|Vector dimension mismatch
|Omit `vector_dimension` for auto-detection, or set it to match your model (e.g. 384, 768, 1536).

|Slow indexing
|Increase `batch_size` to 500–1000 in `provider_config`.

|Milvus Lite lock error
|Set `enable_micro_batching: false` in `global_config`.
|===
