== Data Quality and Enrichment

Quality operators clean, filter, and score documents before expensive embedding and indexing steps.
They are placed between `extract_operator` and `chunker` in a typical pipeline.

=== EdedupOperator (Exact Deduplication)

* **Short name:** `ededup`
* **Category:** Quality

Removes exact duplicate documents by comparing `doc_id_hash` values.
Keeps the first occurrence of any duplicated document.

No configuration is required:

[source,json]
----
{
  "name": "dedup",
  "type": "ededup",
  "depends_on": ["extract"],
  "config": {}
}
----

The `doc_id_hash` column is produced automatically by `ExtractOperator` and `ChunkerOperator`.
If you are using `ededup` without an upstream extract step, add `doc_id_hash` operator first.

The operator removes rows but adds no new columns.

=== LanguageDetect

* **Short name:** `lang_detect`
* **Category:** Quality

Detects the language of each document's text and appends ISO 639-1 language code and confidence score columns.

Two built-in adapters are available:

[cols="1,2,1",options="header"]
|===
|Provider |Languages |Notes
|`fasttext` (default) |176+ |Requires model download; loaded as a singleton
|`langdetect` |55 |No setup required; slower and less accurate
|===

==== Configuration

[source,json]
----
{
  "name": "detect_language",
  "type": "lang_detect",
  "depends_on": ["extract"],
  "config": {
    "doc_column": "content",
    "language_provider": "fasttext",
    "filter_unknown_language": false
  }
}
----

Parameters:

[cols="1,1,1,3",options="header"]
|===
|Parameter |Type |Default |Description
|`doc_column` |string |`content` |Input text column
|`language_provider` |string |`fasttext` |Detection adapter: `fasttext` or `langdetect`
|`filter_unknown_language` |boolean |`false` |Remove documents with unknown/failed language detection
|===

Output columns added:

[cols="1,1,3",options="header"]
|===
|Column |Type |Description
|`lang_name` |string |ISO 639-1 language code (e.g. `en`, `de`, `fr`)
|`lang_score` |float |Confidence score (0.0–1.0)
|===

==== Filter to English Only

Combine with `sql_filter` to keep only English documents:

[source,json]
----
{
  "name": "filter_english",
  "type": "sql_filter",
  "depends_on": ["detect_language"],
  "config": {
    "criteria_list": ["lang_name = 'en'"],
    "logical_operator": "AND"
  }
}
----

=== DocQuality

* **Short name:** `doc_quality`
* **Category:** Quality

Computes a composite document quality score and several sub-metrics.

[source,json]
----
{
  "name": "quality_score",
  "type": "doc_quality",
  "depends_on": ["extract"],
  "config": {
    "doc_column": "content"
  }
}
----

The operator adds quality score columns (`docq_total_words`, `docq_mean_word_len`, `docq_symbol_to_word_ratio`, etc.) that can be used by `sql_filter` for quality thresholding.

=== ReadabilityOperator

* **Short name:** `readability`
* **Category:** Quality

Computes Flesch-Kincaid and related readability scores for each document.

[source,json]
----
{
  "name": "readability",
  "type": "readability",
  "depends_on": ["extract"],
  "config": {
    "doc_column": "content"
  }
}
----

Output columns added include `flesch_kincaid_grade`, `flesch_reading_ease`, `gunning_fog`, `smog_index`, and `automated_readability_index`.

=== RedactionOperator

* **Short name:** `redaction`
* **Category:** Quality

Pattern-based text redaction — replaces regex matches in document content with a masking character.
Use for lightweight redaction when you have known patterns (e.g., specific ID formats, email addresses).
For LLM-based PII detection, use `pii_and_hap` instead.

[source,json]
----
{
  "name": "redact",
  "type": "redaction",
  "depends_on": ["extract"],
  "config": {
    "doc_column": "content",
    "redaction_character": "*",
    "patterns": [
      "\\b[0-9]{3}-[0-9]{2}-[0-9]{4}\\b",
      "\\b[A-Z]{2}[0-9]{6}\\b"
    ]
  }
}
----

=== PIIAndHAPAnnotator

* **Short name:** `pii_and_hap`
* **Category:** Quality

Detects Personally Identifiable Information (PII) and Hate, Abuse & Profanity (HAP) using a configurable LLM provider.

==== PII Types Supported

`BankAccountNumber`, `CreditCardNumber`, `EmailAddress`, `IPAddress`, `PhoneNumber`, `SocialSecurityNumber`

==== Configuration

[source,json]
----
{
  "name": "detect_pii",
  "type": "pii_and_hap",
  "depends_on": ["extract"],
  "config": {
    "provider": "litellm",
    "provider_config": {
      "model_id": "openai/granite4",
      "api_base": "http://localhost:11434/v1",
      "api_key": "${OLLAMA_API_KEY}"
    },
    "expected_redactions": ["pii", "hap"],
    "redaction": true,
    "hap_redaction": false,
    "pii_threshold": 0.5,
    "hap_threshold": 0.8,
    "pii_list": ["EmailAddress", "PhoneNumber", "CreditCardNumber"]
  }
}
----

==== Parameters

[cols="2,1,1,3",options="header"]
|===
|Parameter |Type |Default |Description
|`provider` |string |`litellm` |Detection provider: `litellm` or `watsonx`
|`redaction` |boolean |`false` |Replace detected PII spans with `redaction_character`
|`hap_redaction` |boolean |`false` |Replace detected HAP spans with `hap_redaction_character`
|`expected_redactions` |list |`["pii","hap"]` |Detection types to run
|`pii_list` |list |all 6 types |PII types to detect
|`pii_threshold` |float |`0.5` |Confidence threshold for PII (0.0–1.0)
|`hap_threshold` |float |`0.8` |Confidence threshold for HAP (0.0–1.0)
|`display_pii` |boolean |`false` |Add extra columns with actual PII values (testing only)
|===

==== Output Columns

[cols="1,1,3",options="header"]
|===
|Column |Type |Description
|`pii_count` |integer |Number of PII instances detected
|`hap_count` |integer |Number of HAP instances detected
|`content` |string |Modified content column when `redaction: true`
|===

=== MLEnrichmentOperator

* **Short name:** `ml_enrichment`
* **Category:** Quality

Computes text quality features using data-processing-toolkit enrichment.
Adds multiple signal columns (perplexity, naturalness score, etc.) useful for downstream filtering.

[source,json]
----
{
  "name": "enrich",
  "type": "ml_enrichment",
  "depends_on": ["extract"],
  "config": {
    "doc_column": "content"
  }
}
----

=== SQLFilterOperator

* **Short name:** `sql_filter`
* **Category:** Quality

Filters rows using SQL-like WHERE expressions.
Works on any columns present in the input table — including those added by quality operators.

==== Configuration

[source,json]
----
{
  "name": "filter",
  "type": "sql_filter",
  "depends_on": ["quality_step"],
  "config": {
    "criteria_list": [
      "lang_name = 'en'",
      "docq_total_words >= 50"
    ],
    "logical_operator": "AND"
  }
}
----

==== Parameters

[cols="2,1,1,3",options="header"]
|===
|Parameter |Type |Default |Description
|`criteria_list` |list[string] |`[]` |SQL WHERE expressions as strings
|`criteria_json` |object |`null` |Structured filter criteria with nested logical groups
|`logical_operator` |string |`"AND"` |`"AND"` or `"OR"` for joining `criteria_list` items
|`features_to_drop` |list[string] |`[]` |Column names to remove from output table
|===

Supported comparison operators: `=` `==` `!=` `<>` `>` `<` `>=` `<=` `LIKE` `NOT LIKE` `IN` `NOT IN` `IS NULL` `IS NOT NULL` `BETWEEN`

==== Structured Filter (criteria_json)

For complex nested filter expressions:

[source,json]
----
{
  "criteria_json": {
    "logical_operator": "AND",
    "criteria_list": [
      { "variable": "lang_name", "operator": "=", "value": "en" },
      {
        "logical_operator": "OR",
        "criteria_list": [
          { "variable": "docq_total_words", "operator": ">", "value": 100 },
          { "variable": "page_count", "operator": ">", "value": 5 }
        ]
      }
    ]
  }
}
----

=== Recommended Quality Pipeline

Place quality operators in this order for best results:

[source,json]
----
[
  {"name": "extract",   "type": "extract_operator",   "depends_on": ["ingest"],   "config": {"text_extraction": {"provider": "docling_library"}, "entity_extraction": {"provider": "none"}}},
  {"name": "hash",      "type": "doc_id_hash",         "depends_on": ["extract"],  "config": {}},
  {"name": "dedup",     "type": "ededup",               "depends_on": ["hash"],     "config": {}},
  {"name": "lang",      "type": "lang_detect",          "depends_on": ["dedup"],    "config": {"filter_unknown_language": false}},
  {"name": "quality",   "type": "doc_quality",          "depends_on": ["lang"],     "config": {}},
  {"name": "filter",    "type": "sql_filter",           "depends_on": ["quality"],  "config": {"criteria_list": ["lang_name = 'en'", "docq_total_words >= 50"], "logical_operator": "AND"}},
  {"name": "chunk",     "type": "chunker",              "depends_on": ["filter"],   "config": {"chunk_type": "hybrid", "chunk_size": 512}}
]
----

Rationale for this order:

. `doc_id_hash` before `ededup` — dedup requires the hash column.
. `ededup` before `lang_detect` — no point detecting language on duplicates.
. `lang_detect` before `doc_quality` — quality analysis is language-sensitive.
. `sql_filter` before `chunker` and `embeddings` — avoid embedding low-quality documents.

=== Security Note on PII

The `pii_and_hap` operator should be placed *before* `vectordb` to ensure PII is detected and optionally redacted before documents are indexed.
Documents with `redaction: true` will have their content column modified in-place before downstream operators see it.
See xref:11_production_deployment_and_observability.adoc[Chapter 11] for security best practices.
