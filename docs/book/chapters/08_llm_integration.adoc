== LLM Integration

Several operators — `EmbeddingsOperator`, `ChunkerOperator` (summarisation),
`DocumentClassifierOperator`, `PIIAndHAPAnnotator`, and `ExtractOperator` (entity
extraction) — all share a unified LLM adapter architecture. This chapter explains that
architecture and provides the complete provider reference.

=== Unified Adapter Architecture

The LLM layer is built around three port interfaces:

[cols="1,3",options="header"]
|===
|Port |Purpose

|`LLMInferencePort`
|Text generation / completion (used by classifiers, entity extraction, PII/HAP).

|`LLMEmbeddingPort`
|Dense vector embedding generation (used by `EmbeddingsOperator`).

|`TextDetectionPort`
|PII and HAP detection (used by `PIIAndHAPAnnotator`).
|===

Two adapters implement one or more ports:

[cols="1,2,3",options="header"]
|===
|Adapter |Implements |Description

|`WatsonxAdapter`
|All three ports
|IBM WatsonX.ai native API. Optimised for PII/HAP via the `/ml/v1/text/detection`
endpoint — no prompt engineering required.

|`LiteLLMAdapter`
|`LLMInferencePort` + `LLMEmbeddingPort`
|Proxy adapter supporting 100+ providers (Ollama, OpenAI, Azure, Cohere, AWS Bedrock,
HuggingFace API, etc.) via LiteLLM's unified interface.
|===

The `LLMAdapterFactory` resolves the correct adapter from a `provider` string:

[source,python]
----
from docpipe.core.adapters.llm_adapter_factory import LLMAdapterFactory

adapter = LLMAdapterFactory.create_llm_adapter(
    provider="litellm",
    provider_config={"model_id": "openai/nomic-embed-text", "api_base": "http://localhost:11434"}
)
----

=== Two Integration Patterns

==== Pattern A — Direct Port (most operators)

`EmbeddingsOperator`, `DocumentClassifierOperator`, `PIIAndHAPAnnotator`, and
`ChunkerOperator` (summarisation) use the factory directly — no intermediate service layer:

----
Operator → LLMAdapterFactory → WatsonxAdapter | LiteLLMAdapter → Provider API
----

==== Pattern B — Operator-Specific Adapter Layer (entity extraction only)

`ExtractOperator` entity extraction has its own adapter layer because entity extraction
requires richer prompt engineering and document-type-specific schema handling that does not
fit the general `LLMInferencePort` contract:

----
ExtractOperator → EntityExtractionPort → LiteLLMEntityAdapter | WatsonxEntityAdapter
----

=== Provider Configuration Reference

==== WatsonX

WatsonX is the recommended provider for IBM enterprise workloads. It is the only adapter
that supports the native PII/HAP detection API.

[source,json]
----
{
  "provider": "watsonx",
  "provider_config": {
    "model_id": "ibm/granite-13b-chat-v2",
    "api_key": "${WATSONX_API_KEY}",
    "api_base": "https://us-south.ml.cloud.ibm.com",
    "container_kind": "project",
    "container_id": "${WATSONX_PROJECT_ID}",
    "timeout": 300
  }
}
----

[cols="2,1,3",options="header"]
|===
|Field |Required |Description

|`model_id`
|Yes
|WatsonX model identifier (e.g. `ibm/granite-13b-chat-v2`).

|`api_key`
|Yes
|IBM Cloud API key.

|`api_base`
|Yes
|WatsonX endpoint URL (e.g. `https://us-south.ml.cloud.ibm.com`).

|`container_kind`
|Yes
|`"project"` or `"space"`.

|`container_id`
|Yes
|Project or space UUID.

|`timeout`
|`300`
|Request timeout in seconds.
|===

For embeddings, use `ibm/slate-125m-english-rtrvr` as the model ID and set
`enable_rate_limiting: true` for production workloads (7 req/s limit).

==== LiteLLM

LiteLLM is a unified proxy that supports 100+ providers via a single API surface.
Use it for Ollama (local), OpenAI, Azure, Cohere, AWS Bedrock, and many others.

[source,json]
----
{
  "provider": "litellm",
  "provider_config": {
    "model_id": "openai/nomic-embed-text",
    "api_base": "http://localhost:11434",
    "api_key": "<ollama>",
    "timeout": 120,
    "batch_size": 32
  }
}
----

[cols="2,1,3",options="header"]
|===
|Field |Required |Description

|`model_id`
|Yes
|Model with provider prefix (see table below).

|`api_key`
|Depends
|API key for the provider. Use `"<ollama>"` as a placeholder for Ollama.

|`api_base`
|Depends
|Custom endpoint URL (required for Ollama, Azure, etc.).

|`timeout`
|`120`
|Request timeout in seconds.

|`batch_size`
|`32`
|Texts per batch (for embeddings).
|===

===== LiteLLM Model Prefix Reference

[cols="1,1,2",options="header"]
|===
|Provider |Prefix |Example

|Ollama |`openai/` |`openai/nomic-embed-text`
|OpenAI |`openai/` |`openai/text-embedding-3-small`
|Azure OpenAI |`azure/` |`azure/text-embedding-ada-002`
|Cohere |`cohere/` |`cohere/embed-english-v3.0`
|AWS Bedrock |`bedrock/` |`bedrock/amazon.titan-embed-text-v1`
|HuggingFace API |`huggingface/` |`huggingface/sentence-transformers/all-MiniLM-L6-v2`
|WatsonX via LiteLLM |`watsonx/` |`watsonx/ibm/slate-125m-english-rtrvr`
|===

==== HuggingFace (Embeddings Only)

HuggingFace local inference runs the sentence-transformers model in-process. No API key,
no network call, no cost. Supports CPU, CUDA, and Apple Silicon (MPS).

[source,json]
----
{
  "provider": "huggingface",
  "provider_config": {
    "model_id": "sentence-transformers/all-MiniLM-L6-v2",
    "use_local": true,
    "device": "cpu",
    "batch_size": 32
  }
}
----

==== PIIAndHAPAnnotator

[source,json]
----
{
  "type": "pii_and_hap",
  "config": {
    "provider": "litellm | watsonx",
    "provider_config": { ... },
    "expected_redactions": ["pii", "hap"],
    "pii_threshold": 0.5,
    "hap_threshold": 0.8
  }
}
----

For WatsonX, the `provider_config` is the same as the general WatsonX config above.
WatsonX uses its native `/ml/v1/text/detection` API — no prompts needed.

=== MLEnrichmentOperator

`MLEnrichmentOperator` does not use LLM adapters — it computes statistical features
using the Data Prep Kit library, not a language model. See <<_data_quality_and_enrichment>>
for its full parameter reference.

=== EntityCurationOperator

`EntityCurationOperator` applies schema-driven field filtering and type transformations
to the raw entities produced by `ExtractOperator`. It does not call an LLM.

[source,json]
----
{
  "type": "entity_curation",
  "name": "curate",
  "depends_on": ["extract"],
  "config": {
    "entities_column": "entities",
    "document_type_column": "document_type"
  }
}
----

Four built-in transformations are applied based on field definitions in 40+ bundled
document class schemas:

[cols="2,3",options="header"]
|===
|Transformation |Effect

|`currency_to_numeric`
|Locale-aware currency parsing via Babel. `"$1,234.56"` → `1234.56`.

|`make_date_uniform`
|Normalise dates to ISO 8601 `YYYY-MM-DD`. Uses `datefinder` as fallback.

|`to_number`
|Multi-language number word parsing. `"一千"` → `1000`.

|`weight_to_numeric`
|Locale-aware weight conversion. `"5斤"` (zh_CN) → `2.5` (kg).
|===

=== Choosing an LLM Provider

[cols="2,3",options="header"]
|===
|Use case |Recommendation

|Local development / prototyping
|Ollama via LiteLLM (`openai/` prefix). Free, no API key, offline.

|Production text generation / classification
|LiteLLM (OpenAI or Azure). Reliable, well-documented rate limits.

|IBM enterprise / regulated workloads
|WatsonX native. Governance, audit trail, native PII/HAP detection.

|High-concurrency embedding (offline)
|HuggingFace local. No external calls; scales to 600+ parallel processes.

|Multilingual embeddings
|LiteLLM (Cohere `embed-multilingual-v3.0`).
|===

=== Environment Variables for LLM Providers

[cols="2,3",options="header"]
|===
|Variable |Provider

|`OPENAI_API_KEY`
|OpenAI via LiteLLM.

|`HUGGINGFACE_API_KEY`
|HuggingFace Inference API (only when `use_local: false`).

|`WATSONX_API_KEY`, `WATSONX_API_BASE_URL`
|WatsonX native adapter.

|`OLLAMA_HOST`
|Ollama server base URL (default `http://localhost:11434`).

|`AZURE_API_KEY`, `AZURE_API_BASE`, `AZURE_API_VERSION`
|Azure OpenAI via LiteLLM.
|===

Store all keys as environment variables. Use `+${VAR_NAME}+` substitution syntax in flow JSON:

[source,json]
----
"api_key": "${OPENAI_API_KEY}"
----

=== Troubleshooting

[cols="2,3",options="header"]
|===
|Symptom |Fix

|`ConfigurationError: Unknown provider`
|Use one of: `huggingface`, `litellm`, `watsonx`.

|`ExternalServiceError: Model not found`
|Check `model_id` — verify the model is pulled (`ollama list`) or available on the provider.

|`The api_key client option must be set`
|Set the provider API key env var (`OPENAI_API_KEY`, etc.) or in `provider_config.api_key`.

|Ollama `connection refused`
|Run `ollama serve`. Check `OLLAMA_HOST` if using a non-default host.

|WatsonX `401 Unauthorized`
|Verify `api_key`, `api_base`, `container_kind`, and `container_id` are all set correctly.

|Slow embedding throughput
|For local workloads, switch to HuggingFace `use_local: true`. For cloud, increase `batch_size`.
|===
