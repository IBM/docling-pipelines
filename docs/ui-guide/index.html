The Document AI Bottleneck in Production RAG

In production Retrieval-Augmented Generation (RAG) systems, failures rarely originate in the vector database or LLM generation. They break at the document parsing layer.

Real-world organizational knowledge does not exist in clean, linear markdown. It is trapped inside structurally complex, visual artifacts: multi-column research briefs stored in Microsoft SharePoint, financial statements with merged-cell tables archived in Amazon S3, product slide decks with embedded architecture diagrams on Google Drive, and scanned compliance agreements across local storage volumes.

Standard document ingestion tools treat these files like simple strings of text. They apply basic OCR or naive scrapers that strip coordinate bounding boxes, interleave two-column paragraphs, and dismantle multi-row tables into unreadable sentence fragments. When a vector retriever searches these corrupted chunks, the LLM hallucinates—not because the model is flawed, but because the structural semantics of the document were destroyed before vectorization ever occurred.

💡

The "Scripting Tax" vs. Governed Pipelines: Engineering teams traditionally attempt to patch this with ad-hoc Python glue: combining multiple third-party loaders, handwritten regex for PII filtering, and custom batch loops. These scripts are brittle, lack type safety, offer zero execution visibility, and silently fail when document formats shift.

To solve this foundational data engineering challenge, we built Docling Pipelines (docpipe): an open-source, visual-first document processing platform. Built on IBM's Docling document foundation model, an in-memory Apache Arrow (pa.Table) columnar engine, and an intuitive Carbon-based Visual Canvas, Docling Pipelines enables teams to visually design, govern, and monitor production-scale ingestion workflows from source to vector database.

What You’ll Build

In this deep-dive walkthrough, we will construct an end-to-end, multi-source ingestion DAG using the Docling Pipelines UI. The pipeline will:

  • Unify Multi-Source Ingestion: Connect directly to Microsoft SharePoint, Amazon S3, Google Drive, Box, and local volumes with unified file type filtering.
  • Preserve Layout with Docling: Parse complex layouts, reading order, formula notation, and table structures using the Docling foundation engine and Vision-Language Models (VLMs).
  • Enforce Quality & Compliance in the DAG: Redact sensitive PII (SSNs, credit cards, banking info) and toxic content (HAP) with dedicated visual quality operators.
  • Execute Context-Aware Hybrid Chunking: Leverage Docling's structural AST to chunk along heading hierarchies and keep tabular data intact as cohesive semantic units.
  • Visually Map Schemas to VectorDB: Vectorize via LiteLLM/watsonx/Ollama and visually map PyArrow table features directly into OpenSearch or Milvus index columns via an interactive tearsheet.
  • Monitor Live Execution & Micro-Batching: Observe document throughput, memory overhead, and operator logs in real time on the execution canvas.

Step-by-Step: Assembling the Workflow

1. Multi-Source Document Ingestion (`ingest_source`)

Double-clicking the Ingest Source operator opens its dedicated Properties Panel. Rather than writing SDK boilerplate and custom authentication loops, configure your storage provider directly in the UI.

Figure 3: Ingest Source Properties. Seamless visual configuration for distributed storage providers (Amazon S3, Microsoft SharePoint, OneDrive, Google Drive, Box, Local Filesystem) with inclusion/exclusion filters and token refresh management.

2. Deep Layout Extraction with Docling (`extract_operator`)

At the core of the pipeline is the Extract Operator, powered by IBM's Docling foundation engine. Instead of flattening documents into lossy plaintext, Docling performs multi-modal visual layout analysis to extract hierarchy, tables, reading orders, and visual figures.

Properties Panel — Extract Operator (Docling Settings)
Docling Engine
Click to enlarge

Figure 4: Extract Operator Configuration. Choose between local in-process Docling Library or distributed Docling Serve. Configure hardware acceleration (CUDA GPU, Apple Silicon MPS, or CPU multi-threading), toggle TableFormer table extraction, and activate Vision-Language Models (e.g., Granite-Vision).

3. Governance & Quality Guards (`pii_and_hap` & `doc_quality`)

Strict data privacy mandates that sensitive personally identifiable information (PII) like Social Security numbers, banking IBANs, and patient identifiers—along with toxic or profane text—never enter shared vector databases.

Docling Pipelines integrates quality and safety as first-class DAG operators. Built on the PyArrow table transport, operators like pii_and_hap, doc_quality, ededup (exact deduplication), and lang_detect inspect document content in-flight. You can configure them to redact sensitive tokens in-place, annotate metadata columns for auditing, or drop non-compliant documents completely—without breaking downstream data lineage.

4. Context-Preserving Hybrid Chunking (`chunker`)

Naive chunkers split documents based on arbitrary token counts (e.g., every 512 tokens), slicing multi-page tables in half and disconnecting headers from sub-paragraphs.

Docling Pipelines solves this with Docling's Hybrid Chunker. Because Docling extracted the document's hierarchical Abstract Syntax Tree (AST) in the previous stage, the chunker understands semantic boundaries. Section headers travel with their corresponding paragraphs, and tables remain whole markdown structures rather than severed fragments.

Live Execution & Observability

Once your flow is configured, click Run in the toolbar. The system compiles the DAG, initializes micro-batch scheduling, and navigates to the Live Run Details Canvas (`/flows/:flowId/runs/:runId`).

⚡

Granular Document Accounting: If document 37 in a batch of 500 contains an invalid PDF stream, Docling Pipelines does not crash the entire pipeline. The operator records the failure in the metadata, continues processing the batch, and highlights the skipped/failed item in the UI with the exact stack trace.

Getting Started

You can run Docling Pipelines and the Web UI locally in under 3 minutes:

Terminal (Bash) 
# 1. Clone repository & install backend
git clone https://github.com/docling-project/docling-pipelines.git
cd docling-pipelines

python3 -m venv .venv
source .venv/bin/activate
uv pip install -e ".[dev]"

# 2. Start the FastAPI backend
uvicorn docpipe.api.main:app --host 0.0.0.0 --port 8080

# 3. In another terminal, launch the Web UI
cd frontend
npm install
npm run dev

Open your browser to http://localhost:3000/ui. Create a new project, drag your operators onto the canvas, and build your AI knowledge base!
